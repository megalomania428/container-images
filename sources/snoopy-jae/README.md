# SearXNG MCP server

MCP server [jae-jae/searxng-mul-mcp](https://github.com/jae-jae/searxng-mul-mcp) providing the `search` tool over a SearXNG instance. Upstream is pinned to `a3881c7` in `vars.sh`; patches from `patches/` are applied in filename order and the image is built by the upstream `Dockerfile`. The image entrypoint runs the Streamable HTTP transport on `0.0.0.0:3000` with the MCP endpoint `/mcp` and the health check `/health`.

## Environment variables

- `SEARXNG_URL` – SearXNG instance URL, required.
- `USERNAME` and `PASSWORD` – Basic Auth credentials for SearXNG, optional, set both or none.
- `DEBUG` – `true` enables debug logging, default `false`.
- `SEARXNG_CONCURRENCY` – maximum number of concurrent requests to SearXNG within one `search` tool call, default `3`. Only digits with a value of at least `1` are accepted; any other non-empty value fails the startup with an error message. An unset or empty value selects the default.
- `SEARXNG_DEADLINE_MS` – deadline of one `search` tool call in milliseconds, covering the wait for a free slot, all request attempts and the pauses between them, default `20000`.
- `SEARXNG_ATTEMPT_TIMEOUT_MS` – timeout of one request attempt to SearXNG in milliseconds, including reading the response, default `5000`; an attempt never runs past the call deadline.
- `SEARXNG_ENGINES_TTL_MS` – age in milliseconds after which the engine and category list loaded from SearXNG `/config` is reloaded by the next `search` call with `engines` or `categories`, default `600000`.
- `SEARXNG_ENGINES_REFRESH_MS` – minimal interval in milliseconds between loads of `/config`, successful or not, including reloads after the TTL and for an unknown name, default `60000`.

For `SEARXNG_DEADLINE_MS`, `SEARXNG_ATTEMPT_TIMEOUT_MS`, `SEARXNG_ENGINES_TTL_MS` and `SEARXNG_ENGINES_REFRESH_MS` only digits with a value from `1` to `2147483647` are accepted; any other non-empty value fails the startup with an error message. An unset or empty value selects the default.

`TRANSPORT`, `HOST` and `PORT` do not change the transport or the listening address in the image: the entrypoint passes `--transport=http --host=0.0.0.0 --port=3000`, which override them. With `TRANSPORT=http` set, an invalid `PORT` still fails the startup.

## Patches

- `000-update-node-24.patch` – build and runtime on `node:24-alpine`; `engines` and `@types/node` follow Node 24.
- `001-fix-debug-env-and-verbose-logging.patch` – `DEBUG=true` enables debug logging without changing the entrypoint; SearXNG requests and failed responses are logged in detail.
- `002-per-session-mcp-server.patch` – every HTTP session gets its own MCP server instance, so concurrent clients receive only their own responses and closing one session does not affect others; a `DELETE` rejected by the SDK keeps the session. Regression test: `node --test test/http-session.test.mjs` after the build.
- `003-limit-searxng-concurrency.patch` – requests of one `search` call run with at most `SEARXNG_CONCURRENCY` in flight; results keep the order of `queries`.
- `004-migrate-to-mcp-sdk-v2.patch` – MCP SDK v2: `@modelcontextprotocol/server` and `@modelcontextprotocol/node` replace `@modelcontextprotocol/sdk`, the `search` tool is registered with `McpServer.registerTool` and a strict zod schema; invalid or unknown arguments, search exceptions and calls where every query failed return a tool result with `isError: true`, while a `tools/call` whose `arguments` is not an object (`[]`, `null`, a string) violates the MCP schema and stays a JSON-RPC `-32602` error. Every `search` call that reaches the schema check is logged as `Executing tool` with its arguments and a call rejected by the schema also as `Tool execution failed` with the validation issues; a call whose `arguments` is not an object and a call of an unknown tool are rejected by the SDK with a JSON-RPC `-32602` error before the server code and are not logged. Regression tests: `node --test test/search-validation.test.mjs test/tool-call-logging.test.mjs` after the build.
- `005-retry-searxng-requests.patch` – every query of a `search` call is retried separately on a network error, an attempt timeout, HTTP 5xx or 429 and on empty `results` with a non-empty `unresponsive_engines`, unless every engine reason is `CAPTCHA`, `access denied` or `too many requests`. Pauses follow the go-lib-ci `backoffDelay` schedule (1 s rising by 1 s every 3 attempts up to 7 s) or a longer `Retry-After` of HTTP 429 or 503; the limiter slot stays free during a pause, and no attempt starts when its pause does not fit into `SEARXNG_DEADLINE_MS`. Requests carry `Accept-Language: en` and the cookie `locale=en`. Every query of the result lists `unresponsive_engines` of its last attempt (a retry cut short by the deadline keeps the attempt before it) as `{engine, reason, suspended}` objects, and empty `results` with reasons give `success: false` with `error` `no results: <engine> – <reason>; …`. Suspension and long-ban detection rely on the English reasons: a SearXNG instance that locks `locale` in `preferences.lock` with a non-English `ui.default_locale` translates them, then `suspended` stays `false` and long bans are retried until the deadline. An unusable `SEARXNG_URL` (no `http` or `https` scheme) fails every query at once without retries. Retries and final empty answers are logged as warnings. Regression test: `node --test test/search-retry.test.mjs` after the build.
- `006-validate-searxng-engine-names.patch` – SearXNG silently drops unknown names in `engines` and `categories`, searching with the remaining known names or, when none is left, with its default engines, so a `search` call with `engines` or `categories` first checks them against the engines and categories of SearXNG `/config`. A name is trimmed and matched exactly, then ignoring case, then with `-` and `_` read as spaces, then, for engines only, by shortcut ignoring case (`ddg` → `duckduckgo`); SearXNG receives the matched names without duplicates. An empty or unknown name, or one matching several entries at the same step, returns a tool result with `isError: true` and no search; its text lists such names, the enabled engines with the number of engines disabled by default, which are accepted as well, and for unknown categories all categories. The list is loaded by the first call with names, shared by all sessions and reloaded after `SEARXNG_ENGINES_TTL_MS` and when a name is unknown, at most once per `SEARXNG_ENGINES_REFRESH_MS`; a load is one request with the headers and Basic Auth of searches limited by `SEARXNG_ATTEMPT_TIMEOUT_MS`, concurrent calls share it, and a call waits for it within its `SEARXNG_DEADLINE_MS`. When a load fails, the names are checked against the last loaded list; without one the search runs unchecked; both the failed load and the unchecked search are logged as warnings. Calls without `engines` and `categories` never request `/config`. Regression test: `node --test test/engine-validation.test.mjs` after the build.
